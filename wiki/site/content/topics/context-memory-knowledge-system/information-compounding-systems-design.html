信息复利系统设计

摘要

从 llm-wiki 和 context-infrastructure 往上抽象，可以得到一个更一般的洞察：

> 信息复利设计的关键，不是多存一点信息，而是把未来会反复用到的信号，提前提炼成默认工作面。

这句话看起来简单，但它几乎重新定义了“memory system”该怎么设计。真正重要的，不是系统有没有保存足够多的原始数据，而是未来的工作，究竟站在哪一层上发生。如果未来任务仍然总是回到 raw data，重新检索、重新拼接、重新判断，那么系统只是有存储，没有复利。只有当被提炼过的中间层成为默认工作面，复利才会真正开始。

一、为什么“默认工作面”比“信息存储”更关键

很多系统也会保存历史数据、做标签、做摘要、做索引，看上去已经比一次性问答更先进。但这些能力本身，还不足以构成信息复利。

原因很直接。存储只是把信息留下来，复利则要求未来工作能直接站在已经提炼过的结果上继续进行。如果系统只是把原始数据存得越来越多，而未来问题仍然必须重新回到原始材料里理解一遍，那么它本质上还是在反复支付同样的理解成本。

这就是为什么“默认工作面”这个概念更关键。

所谓默认工作面，指的是未来的大多数任务，首先接触、首先依赖、首先在上面继续推理和行动的那一层。它不一定是最底层，也不一定是最完整的一层，但它必须是最常用、最可调用、最能降低未来理解成本的一层。

从这个角度看，一个系统是否具有复利，不取决于它存了多少数据，而取决于它有没有把高价值信号提前搬到未来工作的起点上。

二、这条洞察如何解释 llm-wiki

llm-wiki 的关键，不只是它有一个 wiki，而是它把 wiki 变成了默认工作面。

未来的大多数问题，不应该直接从原始论文、文章、报告重新开始，而应该先站在这个已经被持续维护的 wiki 上。这里的 wiki 不只是摘要集合，而是一个经过编译的知识中间层。交叉链接、主题结构、对比关系、已有综合，都是为了让后续工作不必每次再从 raw source 重新搭架子。

所以 llm-wiki 真正在做的，不是“保存知识”，而是“把知识编译成未来推理的默认起点”。

一旦这样看，它和传统 RAG 的差别就清楚了。传统 RAG 的主要工作面仍然更接近 raw data 的检索结果，而 llm-wiki 试图把工作面前移到一个已经整理过、结构化过、被持续维护的中间层。原始数据仍然存在，也仍然重要，但它们不再是默认起点，而更像验证层和补充层。

三、这条洞察如何解释 context-infrastructure

context-infrastructure 的关键，也不只是它有 memory、rules、skills，而是它试图把某种已经提炼过的个人信号，变成 agent 的默认工作面。

对于这类系统来说，未来反复出现的任务，并不应该每次都重新从聊天记录、会议痕迹、工作区碎片里推测“这个人可能偏好什么、风格如何、边界在哪”。这些判断如果每次都要重新做，就说明系统没有复利。

所以它需要 observation、pattern、axiom、rules、skills 这些层。它们的意义，不只是多做几层抽象，而是把那些会反复进入未来判断的个人信号提前提纯出来，让 agent 在大多数任务里先站在这些中间层上工作，而不是每次重新回到高噪音原始痕迹。

这里的默认工作面，已经不再是知识页面，而是个体化控制面。它回答的不是“世界上有什么”，而是“这个人通常怎样判断、怎样表达、怎样做取舍”。

原始生活痕迹当然仍然重要，但它们更像训练面、校准面和纠偏面，而不是日常任务的首要工作面。

四、从这里看，设计问题就变了

一旦把信息复利系统理解成“把未来会反复用到的信号提前提炼成默认工作面”，系统设计的核心问题就不再是“怎么把信息都存下来”，而会变成下面这些更本质的问题。

第一，未来到底会反复用到什么信号。

不是所有信息都值得上升成默认工作面。值得上升的，通常是那些会反复参与未来推理、决策、表达、协作或执行的信息结构。它可以是知识、规则、模式、偏好、约束，也可以是某种判断模板。

第二，原始数据离这个信号到底有多远。

如果 raw data 本身已经高信号、主题清晰，那么提炼路径可以很短，默认工作面也可以比较薄。如果 raw data 高噪音、时序化、表达不完整，那么提炼路径就必须更长，否则默认工作面会被噪音污染。

第三，未来工作是否真的默认站在这层上发生。

这一步最容易被忽略。很多系统也会产生中间层，但未来工作并不真正使用它，或者只把它当阅读材料，而不是执行与判断的起点。这样一来，中间层虽然存在，却没有成为默认工作面，也就没有真正创造复利。

所以，信息复利设计真正要回答的，其实不是“该不该做中间层”，而是“哪一层能够成为未来工作的默认起点”。

五、为什么很多系统看起来聪明，却没有复利

很多 AI 系统会让人产生一种错觉：它已经有记忆、有摘要、有索引，所以应该已经具备复利。

但真正的问题往往是，这些能力没有改变未来工作的默认工作面。

比如一个系统也许能自动总结每次会议，但团队下一次做决策时，仍然主要靠重新翻聊天、重新问当事人、重新回忆上下文。那这些总结就更像归档，而不是复利。

又比如一个系统也许记录了大量个人行为数据，但 agent 每次干活时仍然像第一次认识你，仍然需要重新猜你的偏好和边界。那这些记录就更像背景材料，而不是默认工作面。

这也是为什么“默认工作面”是一个很强的辨别标准。它能区分：

  • 只是积累了很多信息的系统
  • 真正让未来工作站在高价值中间层上的系统

前者会越来越大，后者会越来越强。

六、一个更贴近研究工作的例子

比如在边缘计算与网络经济学的机制设计研究里，研究者常常需要围绕一个系统模型和一个优化目标，从头构造机制、做大量理论推导、证明若干性质、再进入实验，最后才发现这个机制根本不值得继续。这里最浪费时间的地方，往往不是实验本身，而是研究者过早为一个还没被有效筛选过的 conjecture 支付了高昂的理论成本。

如果用“默认工作面”这条洞察来看，这个场景里真正应该被提炼出来的，不是论文原文，也不是单次证明过程的全部细节，而是更高层的研究判断信号，例如：哪类问题结构通常对应哪些机制模板，哪些机制在什么约束下大概率无效，哪些参数区间会让某类机制失去意义，哪些 conjecture 值得先做小规模仿真，哪些才值得先投入 formal derivation。

只要这些信号还没有被稳定提炼出来，研究流程就会不断让理论推导充当第一道筛选器。每次新问题到来，研究者都几乎从 raw problem formulation 重新开始，重新猜机制、重新判断值不值得证明、重新为可能无效的方向支付时间。一旦这些研究判断被提炼成默认工作面，循环就会明显加快。新问题进入后，研究者首先调用的就不再是从零开始的推导能力，而是一个已经积累起来的 conjecture screening layer。这样一来，真正开始复利的就不是论文数量，而是“什么值得证明”的研究判断本身。

七、更一般的结论

从这里可以再往上走一步。

信息复利设计最重要的，不是让系统拥有更多记忆，而是让系统拥有更好的默认工作面。所谓更好，指的不是更漂亮，而是更接近未来反复要用到的信号。

所以一个信息复利系统最重要的问题，始终是这一句：

> 未来的高价值工作，到底应该默认站在哪一层上发生？

如果答案仍然是 raw data，那系统再大也很难真正复利。

如果答案是一个被提前提炼出来、能被持续调用、更新、纠偏的中间层，那么复利就开始出现。

这也是为什么真正重要的设计动作，不是“收集更多信息”，而是“把未来会反复进入判断的信号提前搬到默认工作面上”。

从这个意义上说，信息复利系统设计，最终是在设计未来工作的起点。
