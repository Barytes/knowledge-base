notebook/用个人的context构建有护城河的软件.md

现在每个人的 context 都被分散在不同软件里：微信知道关系，飞书知道文档，钉钉知道会议，本地文件知道工作流，ChatGPT / Claude 知道思考过程。但没有一个层知道“我当前的完整世界状态”。所以每次我打开 AI，都要重新解释背景，AI 也经常拿过期 context 回答。

我们想做一个 **personal context layer**：先从各个软件低摩擦收集 context，再在用户进入不同场景时，把正确 context 分发回去。

它有四个核心特性：

1. **持续存在**：不是被 call 才工作，而是在后台持续维护人、项目、决策和 open loops 的状态。

2. **低摩擦**：用户不需要写复杂 prompt，系统从文档、对话、AI 交互、文件变化中自动推断 context。

3. **情景智能**：它通过持续收集和整理个人 context，逐渐形成 contextual intelligence：知道我的长期偏好、判断模式、关系历史、项目状态和想法转向。

4. **主动智能**：它不只是等你问，而是在相关场景中主动把正确背景、旧判断、未闭环事项带回来。

一句话说：

> 我们做的是个人 AI 的 context capture and routing layer：先收集、再分发，让未来所有 agent 不再从零理解你。

四个特性

**1. 持续存在**

不是“有历史记录”，而是 agent 一直有一个后台状态。知道你生活里发生的事，在你不交互的时候也知道，然后持续存在。

用户感知是：我过几天回来，它还知道这件事推进到哪了。它知道某个项目的当前假设、某个人之前的立场、哪些问题还悬着、哪些信息已经过期。

表现为：

  • 自动维护 人 / 项目 / 决策 / open loops 的当前状态
  • 新文档、新聊天、新 AI 对话出现后，后台更新 context
  • 不把每次交互当成新 session
  • 旧判断被新信息覆盖时，能标记 superseded，而不是缝合

**2. 低摩擦**

1）更快的输入，如语音（语音<文字）；2）尽量不输入，后台推断用户要做什么（不prompt<prompt）

用户感知是：我不用写一大段 prompt，它已经知道我大概在处理什么。

表现为：

  • 从文件、聊天、文档、AI 对话、日历、浏览器状态中自动推断 context
  • 用户只需要丢一个链接、转发一段话、语音补一句
  • 不要求用户手动整理成规范格式
  • 不要求每次都回答“你想让我做什么”

更高阶一点是：agent 看到一个新事件后，能自动判断“这应该更新哪个项目/人物/决策状态”。

**3. 情景智能**

通过长期个人上下文积累，越来越懂你的偏好、判断、关系、项目和变化

表现为：

  • 长期积累并整理个人上下文，而不是只读取当前任务窗口
  • 逐渐理解用户的偏好、判断模式、关系历史、项目状态和反复出现的思考主题
  • 能识别用户观点或决策的转向，而不是把新旧信息强行缝合
  • 能区分临时想法、稳定偏好、已确认决策和已经过期的判断
  • 能从分散的文档、聊天、AI 对话和本地记录里，形成对“这个人当前世界状态”的连续理解
  • 在回答或辅助时，不只是检索相关材料，而是基于对用户长期 context 的理解，给出更贴合用户处境的支持

**4. 主动智能**

目前 Agent 的主动提示功能都是定时，没有跟场景结合（例如检测到你要开会，就开始做些啥事，或者检测到你在思考这事，就做啥）

用户感知是：它不是等我问“上次说到哪了”，而是在我需要前已经准备好。

表现为：

  • 检测到相关场景时主动生成 brief
  • 发现旧 context 可能过期时提醒
  • 发现某个 open loop 长期没处理时提示
  • 发现你正在重复解释背景时，自动补上下文
  • 主动 draft，但不擅自执行高风险动作

主动智能的边界很重要：早期只做 **prepare / resurface / draft**，不要直接替用户发消息、改日历、做承诺。

**Product Definition Belief v0.1**

我们相信，下一代 personal agent 的核心不只是更会回答问题，而是能持续维护一个人的 **personal context state**。

今天的 AI 仍然大多是 call-based：用户打开 ChatGPT、Claude、Codex、飞书 AI、钉钉 AI，然后重新解释背景。问题不在于模型不够聪明，而在于每次交互都缺少“这个人当前世界状态”的连续理解。

真正的机会是做一个 **personal context capture and routing layer**：先从分散在 AI 对话、文档、聊天、本地笔记、语音转写里的 context 中低摩擦收集，再持续整理成 people / projects / decisions / open loops / belief changes，最后在用户进入不同工作场景时，把正确 context 分发回去。

**核心问题**

高价值用户的 context 已经严重碎片化：

  • 微信、飞书、钉钉知道沟通上下文
  • 本地文档知道工作过程
  • ChatGPT / Claude / Codex 知道思考过程
  • 语音记录知道线下讨论
  • 浏览器和文章知道外部输入

但没有一个层持续维护：

  • 我现在在推进什么
  • 我对这件事的最新判断是什么
  • 旧判断什么时候失效了
  • 哪些问题还没闭环
  • 哪些人和这个项目相关
  • 下次继续做这件事时，应该带回哪些 context

所以用户的真实痛点不是“找不到某条信息”，而是：

> 每次继续思考、沟通、写作、决策时，都要重新拼接自己的上下文。

这个问题导致 AI 冷启动、沟通重复、判断断裂、旧信息污染新判断，也让个人知识库和聊天历史停留在“存过”，而不是“持续理解”。

**目标用户**

第一批用户应该是 context 密度高、状态变化快、经常跨工具工作的知识工作者。

最核心 ICP：

> founder / product thinker / researcher / AI builder / investor-like operator

他们有几个共同特征：

  • 同时推进多个模糊项目
  • 经常和不同人讨论同一件事
  • 大量使用 ChatGPT、Claude、Codex 等 AI 工具
  • 文档、聊天、AI 对话、本地笔记分散在多个入口
  • 观点会快速变化，但变化过程容易丢
  • 每次写东西、找人聊、继续一个 idea，都要重新恢复上下文

第二层用户可以是：

  • 咨询顾问
  • 投资人
  • 产品经理
  • 研究员
  • 创作者
  • 高强度管理者

但 V0 不要泛化到所有人。第一批最好服务“经常把模糊问题变成判断和行动”的人。

**关键场景**

1. **继续思考一个长期 idea**

用户几天后重新打开一个方向，比如 “persistent personal context layer”。系统自动带出：

  • 当前最新判断
  • 之前被推翻的判断
  • 还没解决的问题
  • 最近相关输入
  • 下一步最值得想的分叉

价值不是总结历史，而是让用户不用重新进入状态。

2. **写给某个关键人的消息**

用户要给深哥、合伙人、投资人或同事写一段话。系统带出：

  • 这个人之前的立场
  • 最近讨论过什么
  • 哪些点对方在意
  • 哪些表达已经说过
  • 当前最适合推进的问题

它不是代写消息，而是让沟通不从零开始。

3. **做一个方向判断**

用户在判断一个产品方向是否值得做。系统带出：

  • 过去关于这个方向的假设
  • 竞品判断
  • 已经变化的观点
  • 反对理由
  • 仍需验证的关键假设

价值是减少“新老观点缝合”，帮助用户看清判断演化。

4. **从 AI 对话切换到真实行动**

用户和 Claude / ChatGPT / Codex 聊了很多，但真正要落到文档、代码、pitch、消息时，context 常常断掉。系统把 AI 对话里的关键结论沉淀成当前 state，并在下一个工具里重新分发。

价值是让 AI 对话不再只是一次性消耗品。

5. **项目状态更新**

某个项目持续推进，系统自动维护：

  • 当前目标
  • 关键决策
  • 参与人
  • open loops
  • 最近变化
  • 风险点
  • 已过期材料

用户不需要手动维护项目 wiki，也不会只得到一堆聊天记录。

6. **发现观点转向**

系统检测到用户从“入口摩擦最重要”转向“持续存在、记忆、主动更重要”。它提示：

> 这个判断发生了转向。是否把旧版本标记为 superseded？

这是非常关键的 magic moment：agent 不只是记住，而是理解用户的判断在变化。

7. **准备一次深度讨论**

不是会议纪要，而是在讨论前生成 context pack：

  • 上次相关讨论的结论
  • 对方可能关心的问题
  • 当前卡点
  • 这次最应该推进的判断
  • 不应该重复争论的旧问题

价值是让讨论更连续，而不是会后多一份记录。

8. **防止旧 context 污染新任务**

用户之前形成过一个判断，但后来已经被新证据推翻。系统在用户再次调用 AI 或写文档时提醒：

> 这个材料里的判断可能已经过期。后来的结论是另一版。

这解决的是普通知识库和 RAG 最容易出错的地方：召回旧信息，但不知道它已经失效。

**一句话**

我们做的不是更好的笔记、录音、搜索或聊天机器人，而是一个持续存在的 personal context layer：它低摩擦收集分散 context，持续维护用户的当前状态，并在关键工作场景中主动分发正确 context。
