# Agent 系统月度执行计划（2026-05-24 至 2026-06-21）

## 摘要

这个月的核心目标是把 `context-core`、`oh-share-it`、`my-little-agent-loop` 收束成一个可以写进简历的生产级旗舰证据包。

`gogo` 不再作为本月主要改造对象。它只保留为已有 workbench / demo / portfolio 入口，除非为了展示 `context-core` 必须做极小适配，否则不继续投入功能开发。

目标叙事不是“做了三个 AI 项目”，而是：

> 构建一个 eval-first 的 agent context infrastructure 系统，覆盖 context core、shared context layer、trace / replay / evaluator loop、真实试点、部署与失败驱动迭代。

项目分工：

| 项目 | 本月角色 | 主要补强 |
|---|---|---|
| `context-core` | 核心 context infra 层 | source registry、context routing、context bundle、trace、eval、writeback |
| `oh-share-it` | context layer 与真实试点主体 | eval、deployment、routing quality、课题组使用 |
| `gogo` | 既有 workbench / demo / portfolio 入口 | 不主动改动，只在需要时做最小展示适配 |
| `my-little-agent-loop` | harness ownership 证据 | trace、replay、evaluator loop、runtime 边界 |
| 行业与求职 | 市场校准 | 公司地图、岗位信号、定向连接 |
| 博弈论与低维结构 | 研究支线 | 小 notebook / memo，不抢主线资源 |

时间范围：2026-05-24 至 2026-06-21。

## 总体成功标准

到 2026-06-21，至少形成以下证据：

1. `oh-share-it` 有一个可运行试点路径。
2. `context-core` 有最小可运行核心：source registry、router、context bundle、trace、eval schema。
3. 有 15 到 20 个真实或半真实问题组成的 eval portfolio。
4. 有 trace / logging / failure taxonomy。
5. `my-little-agent-loop` 有一块明确 runtime ownership：优先 `trace + replay + evaluator loop`。
6. `gogo` 能作为已有 workbench 展示系统，但不承担本月核心开发。
7. 有一篇 case study 或技术长文草稿。
8. 简历中能写出 3 条可信项目 bullet。
9. 完成 10 家目标公司研究，开始 5 次定向投递或外联。

## Week 1：基线与可运行性（2026-05-24 至 2026-05-30）

目标：先抽出 `context-core` 的设计与最小边界，再把现有项目变成可评估的工程对象。

### 主要任务

- 跑通 `oh-share-it` 现有测试、CLI、server、本地 demo。
- 写一页 `oh-share-it` 架构理解笔记：数据流、核心模块、当前缺口。
- 写一页 `context-core` design brief，回答：
  - 它比 `llm-wiki` 多解决什么问题；
  - 它和 `oh-share-it`、`gogo`、`my-little-agent-loop` 的边界；
  - 本月只实现哪些核心对象。
- 定义 `context-core` 最小对象模型：
  - `Source`
  - `ContextUnit`
  - `ContextBundle`
  - `RouteDecision`
  - `Trace`
  - `EvalCase`
  - `WritebackCandidate`
- 给 `oh-share-it` 定义第一版 `eval/` schema：
  - task
  - input context
  - expected behavior
  - scoring fields
- 梳理 `gogo` 当前文档，只判断是否能作为已有展示入口。不做功能改造。
- 梳理 `my-little-agent-loop`，选定本月只做一块：`trace + replay + evaluator loop`。
- 行业：列 20 家目标公司，分为 agent infra、context infra、eval infra、coding agent、research tools。
- 求职：写一版 3 句话定位。
- 博弈论：整理一个问题定义：什么叫“博弈数据的低维结构”。

### 本周结束标准

- 三个 repo 都有明确的本月补强点。
- `context-core` design brief 完成。
- `context-core` 最小对象模型完成。
- `oh-share-it` 能本地跑。
- 第一版 eval schema 出来。
- 目标公司池初稿完成。

## Week 2：oh-share-it 真实试点与 eval（2026-05-31 至 2026-06-06）

目标：用 `context-core` 支撑 `oh-share-it` 试点，把系统从 MVP 推到“有人真实用过、能评测”。

### 主要任务

- 选课题组一个具体方向或项目做试点。
- 收集 15 到 20 个真实问题，记录用户场景。
- 实现 `context-core` 最小可运行链路：
  - source registry
  - route context
  - build context bundle
  - emit trace
  - produce eval record
- 实现最小 eval runner：
  - 输入问题和 context
  - 输出 answer、sources、score stub
- 设计 4 类指标：
  - grounding
  - routing relevance
  - known / judgment / speculation separation
  - next-step usefulness
- 增加 logging / tracing：
  - query
  - context route
  - selected sources
  - answer
  - failure label
- 部署一版最小服务：本地局域网、VPS、Docker 三选一。优先 Docker + README。
- 行业：研究 5 家公司，记录它们买什么能力。
- 求职：把 `oh-share-it` 改写成一条简历 bullet 草稿。
- 博弈论：做一个小 notebook，生成简单 normal-form game 数据，观察 payoff matrix 的低秩或嵌入可能性。

### 本周结束标准

- `oh-share-it` 有真实问题集。
- `context-core` 能生成 context bundle 和 trace。
- 有最小 eval runner。
- 有可展示的 trace / log。
- 有一次真实或半真实试用记录。

## Week 3：my-little-agent-loop 与 context-core 闭环（2026-06-07 至 2026-06-13）

目标：补 runtime ownership，让履历不只依赖上游 agent。

### 主要任务

- 在 `my-little-agent-loop` 实现 `trace + replay + evaluator loop`。
- trace 至少记录：
  - user task
  - context bundle
  - tool calls
  - model output
  - decision points
  - final result
  - failure label
- replay 可以重跑 5 到 10 个固定 task。
- evaluator 可以对 replay 输出做基础打分或人工评分入口。
- 把这套机制和 `oh-share-it` eval 对齐，说明它如何服务 context infra 质量闭环。
- 把 `my-little-agent-loop` 的 trace / replay / evaluator loop 与 `context-core` 的 `Trace` / `EvalCase` 对齐。
- 给 `context-core` 增加 5 到 10 个 regression cases。
- 只更新 `gogo` 的展示说明，不改功能：
  - README 小节
  - demo flow
  - 它如何作为已有 workbench 观察 `context-core` 输出
- 行业：再研究 5 家公司，补岗位信号表。
- 求职：定向联系 2 个人，目标是请教或反馈，不是立刻求内推。
- 博弈论：写半页 memo，把低维结构和 agent eval / multi-agent behavior 的关系讲清楚。

### 本周结束标准

- `my-little-agent-loop` 有一块清楚的 harness ownership。
- `context-core` 有可回放的 regression cases。
- `gogo` 作为已有展示入口的边界讲清楚。
- 三个项目可以合成统一叙事。

## Week 4：打磨成简历级证据包（2026-06-14 至 2026-06-21）

目标：从工程推进转成市场可识别信号。

### 主要任务

- 写一篇 case study：`Building an eval-first context layer for research agents`。
- case study 至少覆盖：
  - 问题定义
  - 架构
  - `context-core`
  - eval
  - trace
  - 真实试点
  - 失败案例
  - 改进前后对比
- 三个 README 更新到简历可读状态：
  - `context-core`：eval-first context routing / bundle / trace / writeback
  - `oh-share-it`：context layer + eval + deployment + trial
  - `gogo`：existing workbench / demo entry，不作为本月核心开发
  - `my-little-agent-loop`：trace / replay / evaluator harness
- 简历项目区写 3 条 bullet，每条都包含：
  - 结果
  - 技术
  - 证据
- portfolio / GitHub profile 更新，突出 `Agent Systems Engineer` 主线。
- 行业：完成 10 家重点公司 shortlist。
- 求职：投递或定向联系 5 个最匹配机会。
- 博弈论：只保留一个公开小节或 appendix，不作为主项目。

### 本周结束标准

- 至少一个项目能被称为旗舰项目。
- 有 eval、trace、deployment、真实试点、case study。
- 简历里能写，不心虚。

## 每周时间配比

| 类别 | 比例 | 说明 |
|---|---:|---|
| 旗舰项目工程推进 | 70% | `context-core`、`oh-share-it`、`my-little-agent-loop` |
| 文档、case study、简历叙事 | 15% | 把工程结果变成市场信号 |
| 行业研究与求职外联 | 10% | 每周公司研究与少量连接 |
| 博弈论与低维结构 | 5% | 保留研究火种，不抢主线 |

## 每日最低动作

如果当天状态不好，只完成三件最小动作：

1. 推进一个可验证工程任务。
2. 记录一个失败、发现或设计决策。
3. 更新一次本周 checklist。

## 压缩结论

这个月的判断标准不是功能数量，而是市场是否能看懂你经营过一个 agent context / harness / eval 系统。

真正要交付的是一个证据包：

> 一个 `context-core` + 一个真实试点 + 一套 eval + 一套 trace / replay / evaluator loop + 一个已有 workbench 展示入口 + 一篇 case study + 一组简历 bullet。
