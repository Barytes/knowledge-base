# AI 泡沫破裂后的死亡名单与留存层

把 2000 年互联网泡沫迁移到当前 AI 周期时，关键不是预测某一家公司的短期涨跌，而是看前沿公司是否真的控制了模型、分发、工作流、数据权限、执行环境、垂直服务交付和可验证 ROI。2026 年的主战场已经不是简单 wrapper 会不会死，而是复杂 agent / workflow / vertical AI 公司能不能穿越信任、毛利、治理和交付规模化这几道关。

**来源：** 基于本库已有页面的二次综合，主要参考 [AI 产业与投资判断框架](../../frameworks/AI产业与投资判断框架.md)、[AI 产业分层地图（2026）](AI产业分层地图.md)、[AI 产业的付钱地图（2026）](AI产业的付钱地图.md)、[AI Infra 的抗模型吞噬地图](AI-Infra的抗模型吞噬地图.md)、[AI 时代的投资与生存法则](AI%20时代的投资与生存法则.md)、[衰退期的创业环境与技术判断](衰退期的创业环境与技术判断.md)。2026-07-01 追加外部调研，参考 [Menlo Ventures 2025 enterprise AI report](https://menlovc.com/perspective/2025-the-state-of-generative-ai-in-the-enterprise/)、[a16z Top 100 Gen AI Consumer Apps - 5th Edition](https://a16z.com/100-gen-ai-apps-5/)、[Claude Code](https://www.anthropic.com/claude-code)、[OpenAI Codex](https://openai.com/codex/)、[Cognition Devin](https://www.cognition.ai/blog/introducing-devin)、[Harvey](https://www.harvey.ai/)、[Abridge](https://www.abridge.com/) 等公开页面。

## 2026-07-01 修正

原答案把“会死的公司”过多压在 `prompt wrapper`、普通 chatbot builder、简单 RAG wrapper、简单 agent demo 这些 2023-2024 年常见形态上。这个判断方向不完全错，但已经不是 2026 年前沿公司的主战场。

到 2026 年，前沿公司更像下面几类：

| 类型 | 代表信号 | 关键控制点 |
|---|---|---|
| Coding agent / 软件生成工作面 | `Claude Code` 能读代码库、改文件、跑命令；`OpenAI Codex` 强调多 agent 并行、worktree、cloud environment、team skills；`Cursor`、`Lovable`、`Replit`、`Devin` 等把代码生成推进到 IDE、repo、部署和 review 工作流 | 默认开发工作面、repo context、执行环境、测试验证、团队标准 |
| 企业横向 agent / work AI | `Glean`、`Writer`、`Salesforce Agentforce` 这类平台试图连接企业知识、权限、应用和自动化 | 企业数据权限、system of record、workflow automation、治理 |
| 客服 / 客户体验 agent | `Sierra`、`Decagon`、`Intercom` 等不是普通客服机器人，而是在争夺企业客户交互、业务动作和品牌体验入口 | 客户上下文、业务系统写回、质量控制、品牌风险、企业集成 |
| 垂直专业工作流 | `Harvey` 覆盖法律研究、合同、尽调、诉讼、shared spaces、agents；`Abridge` 覆盖就诊前、中、后临床文档和后续动作；医疗、法律、金融、会计等都在从 copilot 走向 workflow | 行业 know-how、合规、专业验收、真实 ROI、采购路径 |
| AI-native consumer / prosumer 应用 | a16z 榜单里的 `ChatGPT`、`Gemini`、`Perplexity`、`Character AI`、`Midjourney`、`ElevenLabs`、`Suno`、`Kling`、`Manus` 等已经不是简单聊天壳，而是在模型、内容形态、社区、工具链和分发上分化 | 用户心智、创作工作流、内容供给、移动分发、社交/社区 |
| 推理、模型路由、开发者基础设施 | `OpenRouter`、`fal`、`Modal`、`Baseten`、`Together`、`Braintrust`、`LangSmith` 等围绕模型接入、推理、评测、部署和观测 | 成本、延迟、可靠性、模型选择、eval、debug、运维 |

所以，修正后的判断应该是：

> **前沿 AI 公司已经普遍越过了“wrapper”阶段。真正要问的是：它是在拥有一个新的工作面、服务交付网络和控制点，还是只是把复杂 demo 包装成高估值软件公司。**

Menlo 的 2025 enterprise AI report 也支持这个迁移：企业生成式 AI 支出已经从实验走向应用和生产，应用层拿到超过一半支出；coding 成为最明确的 killer use case；vertical AI 尤其医疗已经有明确预算；企业更倾向购买成熟 AI solution，而不是都自己 build。a16z 的 consumer 榜单则显示，消费端也不是一堆 ChatGPT copycat，稳定下来的公司横跨通用助手、搜索、陪伴、图像、视频、语音、音乐、生产力和 app generation。

这意味着，`prompt wrapper 会死` 只能解释尾部公司，不能解释当前前沿公司。

## 核心判断

如果把 2000 年互联网泡沫迁移到当前 AI 周期，最稳的类比不是“哪些公司股价会跌”，而是：

> **会破的不只是薄 wrapper，而是那些无法把 agentic capability 转化为可规模化收入、可治理执行、可验证 ROI 和可持续毛利的公司；会留下的是 AI 作为新计算层、工作流重写层、服务交付层和真实系统基础设施。**

2000 年后留下来的不是 Pets.com，而是搜索、电商、支付、广告、宽带、云和后来的社交网络。同理，AI 泡沫后大概率留下来的也不是今天每一个 AI startup，而是：

- 模型能力作为新的智能供给
- 算力、数据中心、电力和推理基础设施
- eval、observability、security、agent runtime、context / memory governance
- coding、企业 workflow、医疗、法律、金融等能证明 ROI 的垂直应用
- 被 AI 重写后的组织流程、岗位结构和软件工作面

所以真正的问题不是“AI 是不是泡沫”，而是：

1. 哪些公司只是站在泡沫叙事上。
2. 哪些公司控制了泡沫破裂后仍然稀缺的资源。
3. 哪些层即使公司换一批，需求也会继续存在。

## 一、2026 年更值得看的死亡风险

### 1. 复杂 agent 兑现不了可靠性

前沿公司都在讲 agent，但企业真正买的不是“自主性”，而是结果。只要 agent 能写、发、改、下单、退款、审批、操作系统，它就会遇到：

- 谁授权
- 谁验收
- 谁回滚
- 谁负责错误
- 谁能解释轨迹
- 谁能隔离高风险动作

所以复杂 agent 公司会死在另一件事上：不是“不够 AI”，而是太 AI、太能动，却没有对应的治理结构。不能把 proposal、execution、verification、human approval、audit trail 做成系统的公司，很难进高价值生产场景。

### 2. AI 服务公司毛利不像软件

很多前沿 vertical AI 公司看起来像 SaaS，实际可能更像 AI-enabled service。它们需要 forward-deployed engineer、法律/医疗/金融专家、客户成功、定制集成和人工 QA。

这不一定坏。Palantir 式、服务嵌入式、AI FDE 式公司也可能很值钱。但如果公司估值按 software multiple 算，交付却按 consulting / BPO 成本结构跑，就会在泡沫破裂时被重定价。

更准确的死亡问题是：

```text
它是在用 AI 把服务产品化，还是在用 AI 叙事把服务软件化估值？
```

### 3. App generation / vibe coding 平台的留存和维护税

`Cursor`、`Lovable`、`Replit`、`Devin`、`Codex`、`Claude Code` 所在方向是真前沿，不是 wrapper。但这条线也有新风险：

- 生成 app 容易，长期维护难
- demo 到 production 的距离仍然大
- 非技术用户能创建，但未必能判断架构、权限、安全和数据模型
- AI 生成代码带来 cleanup tax
- 如果底层模型或 IDE 平台内置类似能力，独立平台要靠工作面、社区、部署、review、team workflow 留住用户

所以这类公司不会因为“wrapper”死，而会因为不能从 creation novelty 迁移到 production workflow 而死。

### 4. 垂直 AI 的 ROI 真实，但 TAM / 交付边界可能被高估

`Harvey`、`Abridge`、`Ambience`、`Eve`、`Rillet`、`Numeric` 这类 vertical workflow 公司，比普通 SaaS+AI 更有机会。它们接近真实预算、专业任务和高痛点。

但泡沫风险也更具体：

- 行业采购慢
- 合规和责任边界重
- 专业验收不可完全自动化
- 不同客户 workflow 差异大
- 高价值任务可能需要大量专家参与
- 市场可能没有估值暗示的那么横向可复制

这类公司会留下来的前提，不是“行业 + AI”这个标签，而是能否把专业服务拆成可复用 workflow，并在保持质量的同时扩毛利。

### 5. Customer support agent 会被系统写回能力分化

`Sierra`、`Decagon`、`Intercom` 这条线不是普通 chatbot builder。它们争夺的是企业客户交互入口。

但这个赛道也会剧烈分化：

- 只会回答问题的会被平台和 incumbent 吃掉
- 能完成退款、改订单、查账户、升级工单、个性化挽留、生成业务洞察的才有机会
- 失败会直接伤害品牌和收入，容错比内部效率工具低

所以判断标准不是“是不是客服机器人”，而是：

```text
它是否拥有客户上下文 + 业务动作权限 + 质量控制 + 可审计写回？
```

### 6. 模型公司从“能力竞争”转向“分发和资本结构竞争”

二线模型公司仍然危险，但理由要更精确。

危险不是它们只是 wrapper，而是：

- frontier training 和推理资本开支巨大
- enterprise buyer 更集中使用少数领先模型
- 开源 / 开放权重模型持续压低差异化
- 大平台有云、分发、数据和企业关系
- 垂直模型如果不能绑定工作流，容易变成可替换 backend

所以模型公司要留下，必须至少占住一个控制点：最强能力、最低成本、开源生态、国家/区域合规、垂直 workflow、企业私有部署或平台分发。

### 7. Consumer AI 的风险从“copycat”变成 retention / identity / safety / IP

消费端也不能简单说“没有分发的通用 app 会死”。a16z 的榜单显示，稳定玩家已经横跨 general assistant、search、companion、image/video/music、voice、productivity、app generation 和 model hosting。

真正风险在于：

- 用户是否高频留下
- 内容供给是否可持续
- 是否有社交或创作网络效应
- 是否受平台分发和 app store 规则影响
- 是否有版权、深伪、未成年人、安全和陪伴依赖风险
- 是否会被 `ChatGPT`、`Gemini`、`Grok`、`Meta AI` 这类默认入口压缩

也就是说，消费 AI 的死亡风险已经从“是不是 ChatGPT copycat”升级成“有没有身份、内容、社区、创作工具链和分发控制”。

## 二、仍然可能留下来的层

“留下来”也不一定等于今天某家公司原样胜出。更准确地说，是这些层的需求会穿越泡沫。

### 1. 默认工作面

能成为用户每天工作入口的公司会留下：

- IDE / repo / terminal / PR workflow
- enterprise search / work graph
- legal workspace
- clinical workflow
- customer support console
- browser / operating system / office suite
- creator workspace

2026 年的前沿公司越来越像“新工作面”，不是单点工具。

### 2. 可治理执行环境

Agent 真正进入生产，需要 sandbox、权限、审批、回滚、日志、评测、错误恢复和人类接管。这个层不会因为模型变强消失，反而会因为模型能行动而更重要。

### 3. 专业服务产品化层

法律、医疗、金融、会计、客服、销售、政府等行业里，真正的机会不是“AI 给建议”，而是把一段原本由人完成的专业服务拆成：

```text
上下文获取 -> 草拟 / 推理 -> 专业检查 -> 系统写回 -> 审计留痕 -> 结果交付
```

能把这条链产品化的公司会留下。

### 4. 模型和推理成本控制层

模型能力会继续商品化一部分，但成本、延迟、routing、multi-model orchestration、observability、eval 和安全不会消失。企业不会只买“最聪明模型”，还会买“能稳定、便宜、可控地用模型”。

### 5. 真实分发和用户心智

无论 to B 还是 to C，分发重新变成关键控制点。前沿 AI 公司已经不只是拼功能，而是在拼：

- PLG
- 默认入口
- 团队协作网络
- 行业采购路径
- creator / companion 社区
- model ecosystem

## 三、泡沫后留下来的用户需求

如果从用户需求而不是公司类型看，AI 泡沫破裂后更可能留下来的不是“我要一个 AI 产品”，而是几类更朴素、反复存在、愿意付钱或付时间的需求。

### 1. 把任务做完，而不是得到建议

用户不会长期为“听起来聪明的回答”付高价，但会为完成任务付钱。

留下来的需求包括：

- 代码改完、测试跑过、PR 可 review。
- 客服问题解决，订单、退款、账户状态真的被改对。
- 医生看诊后文档、编码、医嘱和 follow-up 被正确处理。
- 法律合同、尽调、研究、诉讼材料能进入下一步工作。
- 报告、表格、分析、发票、合规材料能被提交或写回系统。

这对应的是 `answer -> action -> verified outcome` 的迁移。泡沫会挤掉只会“说”的产品，但不会挤掉用户对“替我把事办成”的需求。

### 2. 降低专业服务成本，同时保持质量边界

很多行业里，用户真正买的是专业服务，不是软件界面。法律、医疗、会计、金融、咨询、客服、销售运营都属于这一类。

泡沫破裂后留下来的需求是：

- 更便宜地获得专业初稿。
- 更快完成高重复但高责任的文档工作。
- 把专家时间从信息整理中解放出来，留给判断和责任。
- 让小客户也买得起过去只有大客户能买的服务。

关键是“便宜”不能以质量失控为代价。所以能留下的不是泛泛自动化，而是带有专业验收、引用、审计、人工接管和责任边界的服务产品化。

### 3. 在复杂系统里安全执行

企业用户不是缺一个聊天框，而是缺一个能在复杂系统中安全行动的工作主体。

留下来的需求包括：

- 连接多个系统并理解权限。
- 在 CRM、ERP、工单、代码库、文档库、邮件、日历之间执行动作。
- 高风险动作需要审批。
- 出错后能追踪、回滚、恢复。
- 管理层能看到成本、效果、失败原因和责任链。

这就是 agent runtime、workflow harness、security、observability 和 governance 需求的用户侧表达。

### 4. 把个人或组织上下文带进每一次工作

用户反复问 AI，很大一部分痛苦来自“每次都要重新解释我是谁、我在做什么、我已经判断过什么”。

留下来的需求包括：

- 记住项目背景、偏好、约束和历史决策。
- 区分哪些信息可信、过期、冲突、敏感。
- 在需要时自动调出相关上下文。
- 把一次任务的产物写回知识库、项目文件或组织记忆。
- 多人协作时保持权限边界和来源追踪。

所以 context / memory / knowledge governance 不是抽象 infra，而是在满足一个很直接的用户需求：不要让我每次从零开始。

### 5. 让软件和数据变得可操作

过去很多软件只是把信息放在界面里。AI 之后，用户更想要的是“我说目标，系统帮我跨软件完成操作”。

留下来的需求包括：

- 从文件、网页、数据库、代码库、截图、会议记录里抓取信息。
- 把信息转成行动。
- 在多个工具之间搬运、校验、更新。
- 把隐藏在系统里的流程变成可委托任务。

这解释了为什么默认工作面很重要。用户不是单纯要更好的 UI，而是要能把已有软件、数据和流程变成可执行对象。

### 6. 更快地创造和迭代数字作品

泡沫会压缩一批只靠 novelty 的 app generation 产品，但不会消灭“更快把想法变成作品”的需求。

留下来的需求包括：

- 把想法变成可运行 demo。
- 把 demo 变成可维护产品。
- 生成图像、视频、音乐、网页、脚本、数据分析、自动化流程。
- 快速试错、比较版本、发布、收集反馈。

这里真正留下的不是“vibe”本身，而是创作速度、反馈速度和从想法到可验证作品的路径变短。

### 7. 在信息过载中获得判断辅助

搜索、研究、阅读、比较、筛选不会消失。尤其当内容更多由 AI 生成后，用户更需要判断辅助。

留下来的需求包括：

- 从大量材料中找到可信来源。
- 区分事实、推断、观点和噪音。
- 比较多个方案的成本、风险和证据。
- 把研究结果整理成可行动决策。
- 在高风险判断前发现遗漏和反例。

这类需求不会只由通用搜索满足。真正有价值的是面向具体任务、具体领域、具体上下文的 research / decision workflow。

### 8. 陪伴、表达和身份建构

消费端 AI 泡沫破裂后，也不会只留下生产力工具。陪伴、表达、娱乐和身份需求会继续存在。

留下来的需求包括：

- 有人随时听我说话。
- 帮我表达一个形象、声音、角色或故事。
- 生成图片、视频、音乐、虚拟角色。
- 在社区或创作平台里获得反馈。
- 用 AI 扩展自己的表达能力和社交身份。

这类需求的风险在安全、未成年人、依赖、版权和平台分发，但需求本身不会因为泡沫破裂消失。

### 9. 降低使用 AI 本身的成本和风险

当 AI 进入工作流后，用户会产生一类二阶需求：不是“AI 能做什么”，而是“我如何安全、便宜、稳定地用 AI”。

留下来的需求包括：

- 更低推理成本。
- 更低延迟。
- 模型选择和 fallback。
- 输出质量评测。
- 数据不泄露。
- 权限不越界。
- 行为可观测。
- 结果可复现。

这就是推理基础设施、model gateway、eval、observability、安全治理会留下的原因。

### 10. 重新组织人类工作

AI 泡沫破裂后，组织仍然会继续问：

- 哪些工作该交给 AI。
- 哪些判断必须留给人。
- 团队人数是否可以更少。
- 管理层是否还需要这么多信息传递。
- 专家如何用 AI 放大自己，而不是被替代。

这不是某个产品功能，而是组织需求。它会催生培训、咨询、workflow redesign、AI FDE、内部平台、岗位重组和新的管理工具。

## 四、用 2000 年事实反向压测用户需求判断

2000 年互联网泡沫给这个判断最大的压力，不是“互联网需求后来不存在”，而是相反：很多需求后来都存在，但对应的公司仍然死了。

历史事实可以压成几类：

- 用户确实需要在线买东西，但 `Pets.com`、`eToys`、`Boo.com` 等公司没有穿越周期，`Amazon` 后来穿越了。
- 用户确实需要食品杂货和本地履约便利，但 `Webvan` 在资本开支、履约密度、时机和单位经济上过早过重。
- 用户确实需要信息入口和内容导航，但大量门户、内容站和流量包装公司消失，搜索广告和少数平台留下。
- 用户确实需要社区、个人主页和线上身份，`GeoCities` 这类公司没有成为最终赢家，但社交网络、UGC 平台和创作者工具后来留下。
- 用户确实需要更快的网络和数据传输，很多电信、光纤和数据中心投机公司破产或重组，但宽带、云和数据中心后来成为基础设施。

所以，2000 年事实会迫使前面的 claim 加一个更严格版本：

> **泡沫后留下来的不是“被证明存在的需求”，而是能被持续、经济、可信、规模化满足的需求。需求存在只能证明方向可能对，不能证明公司、产品形态或估值正确。**

按这个标准反查前面的十类需求，可以得到三组结论。

### 1. 通过压力测试的强需求

**把任务做完**仍然是最强需求。互联网泡沫后留下来的电商、搜索、支付、广告、云，本质上都不是“展示网页”，而是把某类任务完成得更快、更便宜或更可靠。迁移到 AI，就是从回答走向 verified outcome。

**降低专业服务成本**也通过。2000 年后的互联网没有消灭零售、媒体、旅行、招聘、金融服务，而是改写了交付和分发。AI 对法律、医疗、会计、软件开发的类比也成立，但前提是不能只降低表面生成成本，还要降低完整交付成本。

**在复杂系统里安全执行**通过。2000 年后真正留下来的基础设施都解决了信任和交易摩擦：支付、身份、物流、云稳定性、搜索质量。AI agent 如果要进入生产，也必须解决权限、审计、回滚、验收和责任。

**让软件和数据变得可操作**通过。互联网把线下目录、商品、广告、通信、文件和计算资源变成可搜索、可交易、可调用的对象。AI 如果是新的操作层，它留下来的价值也会体现在把软件、文档、数据和流程变成可委托对象。

### 2. 需要降级表述的需求

**把上下文带进每一次工作**是真需求，但更像中间需求，不一定是终端用户单独付钱的东西。2000 年后用户不是为“数据库”“cookies”“推荐系统”本身付钱，而是为更好的搜索、购物、社交和工作体验付钱。AI 的 context / memory 也类似：它必须嵌入任务完成、工作面或组织系统，才会变成强需求。

**降低使用 AI 本身的成本和风险**也更像 builder / enterprise buyer 的需求。普通用户不会长期关心 model gateway、eval、observability，但企业、开发者和平台会关心。这类似 2000 年后用户不直接购买光纤协议或服务器调度，但云、CDN、支付风控和广告基础设施成为真实生意。

**重新组织人类工作**是真变化，但不是一个自然的单品类需求。2000 年后企业确实重组了渠道、客服、营销、供应链和 IT，但购买的通常是 CRM、ERP、电商平台、广告系统、云服务、咨询和外包，而不是一个叫“组织重构”的产品。AI 这里也要拆成具体预算和落地面。

### 3. 最容易被泡沫放大的需求

**更快创造和迭代数字作品**会留下，但最容易被 novelty 高估。2000 年时网页、个人主页、Flash、门户内容、在线媒体都很热，最后留下的是具备分发、工具链、社区或商业闭环的平台。AI app generation、图像、视频、音乐工具也一样：创作需求是真的，但没有留存、分发和商业闭环的产品会死。

**陪伴、表达和身份建构**会留下，但不能直接用企业 ROI 框架解释。2000 年后的社交、游戏、UGC 和社区证明了身份与表达需求的强度；同时也证明这个方向受平台分发、网络效应、内容治理和安全问题强约束。AI companion 和虚拟角色方向会留下需求，但公司会高度分化。

**信息过载中的判断辅助**会留下，但会被默认入口吸收。2000 年后“帮我找到信息”是超级需求，但最终不是大量人工目录站留下，而是搜索、推荐、社交分发和专业数据库留下。AI research / decision workflow 也必须有可信来源、任务上下文和行动闭环，否则会被通用搜索和默认助手压缩。

### 压测后的修正结论

因此，前面十类用户需求不应该被理解成十个同等强度的赛道。更准确的分层是：

1. **终端强需求**：完成任务、降低完整交付成本、安全执行、让数据和软件可操作。
2. **基础设施型需求**：context / memory、AI 成本风险控制、eval、observability、权限和治理。
3. **消费与表达型需求**：创作、陪伴、身份、信息判断，但必须通过分发、社区、内容供给、信任和留存再验证。
4. **组织转型型需求**：真实存在，但通常会拆成 consulting、workflow redesign、内部平台、AI FDE、培训和管理系统，而不是单独成为一个大而泛的产品。

2000 年给 AI 泡沫最有用的提醒是：

```text
真实需求 + 错误时机 + 错误资本结构 + 错误履约模型 = 公司死亡，需求留下。
真实需求 + 分发入口 + 单位经济 + 信任机制 + 基础设施成熟 = 穿越周期。
```

## 五、旧式薄包装仍会死，但不是前沿主战场

这里的“死”不一定是破产。也可能是被平台内置、被模型原生能力吞掉、被并购、估值归零、从独立公司退化成小功能。

### 1. Prompt wrapper 和内容生成小工具

典型结构是：

```text
用户输入 -> prompt -> LLM -> 文案 / 图片 / 总结 / 邮件 / 标题
```

这类产品危险，不是因为没有需求，而是因为价值主要来自底层模型能力。一旦 `ChatGPT`、`Claude`、`Gemini`、企业 SaaS 或操作系统把这些能力内置，独立产品的差异会迅速变薄。

死亡信号：

- 没有独有数据
- 没有 workflow lock-in
- 没有长期状态
- 没有评测、权限、审计和系统集成
- 用户只是把它当“便宜一点的模型入口”

### 2. 普通 chatbot builder

“上传文档生成客服机器人”如果只是 `chunk -> embedding -> vector search -> stuff prompt`，很容易被平台吃掉。

它的问题不是 RAG 没价值，而是基础 RAG 会商品化。企业真正难的是 ACL、freshness、lineage、citation、删除、审计、效果评测、人工接管和业务系统写回。

### 3. 简单 agent framework

只提供 `tools + planner + executor` 的 agent framework 很危险。

模型会越来越会 plan、call tools、修正错误；平台 API 也会把常见 tool use 模式产品化。真正不会轻易消失的是 sandbox、权限、长任务、状态持久化、rollback、human-in-the-loop、tracing 和 replay。

也就是说，demo agent 会死，production runtime 可能留下。

### 4. 只靠“AI 版旧 SaaS”的中间层应用

很多公司只是把旧 SaaS 加一层 AI：

- AI CRM
- AI HR
- AI PM tool
- AI BI
- AI notes
- AI dashboard

如果它只是把原来的 UI 和流程稍微自动化，没有改写结果交付方式，就会掉进本库反复提到的“中间地带”：

- 没有顶级判断密度
- 没有极致成本优势
- 没有深行业 workflow
- 也没有默认分发入口

这类公司很容易被两端夹击：一端是大平台内置 AI，另一端是真正垂直深入的 workflow / harness 公司。

### 5. 缺少分发的通用 AI app

通用 app 很容易被默认入口吞掉。

如果一个产品面向所有白领、所有学生、所有创作者，但没有浏览器、办公套件、手机系统、企业账号体系、开发环境或社交网络入口，它要单独争夺用户注意力会很难。

这类产品不是不能活，而是必须有非常强的网络、品牌、数据或工作面优势。否则会变成短期 consumer AI 榜单里的流量波动。

### 6. 资本开支过重、但没有利用率优势的算力公司

算力层会留下，但不代表每个算力公司都会赢。

风险在于：

- 高债务买 GPU
- 没有稳定大客户
- 没有调度、能耗、网络、运维或成本优势
- 只靠“AI 算力永远短缺”的融资叙事

这一层可能像互联网泡沫里的电信和光纤：基础设施方向正确，但过度铺设、资本结构错误的公司仍然会死。

### 7. 没有差异化的二线模型公司

基础模型会留下，但模型公司未必都能独立留下。

模型层需要巨额算力、顶级人才、数据、分发、企业信任和资本耐心。未来更可能形成少数大闭源模型、若干强开源生态、以及被大平台吸收的模型能力。

二线模型公司如果没有：

- 明确技术领先
- 成本优势
- 开源生态
- 垂直场景
- 分发入口
- 战略资本支持

就很容易被挤成 API 价格战里的供应商，或者被并购。

## 六、原判断中仍然成立的留存层

“留下来”也不一定等于今天某家公司原样胜出。更准确地说，是这些层的需求会穿越泡沫。

### 1. 控制算力、云、芯片、电力和数据中心的公司

AI 的底层约束是资本开支、芯片、数据中心、电力和网络。只要模型和推理需求继续增长，这层就不会消失。

典型位置包括：

- 芯片与系统：`NVIDIA`、`AMD`、`TPU` 生态
- 云和集群：`AWS`、`Azure`、`GCP`、`Oracle`、`CoreWeave`
- 数据中心、电力、光通信、冷却、网络等配套基础设施

但这里要区分：底层需求会留下，不代表所有高估值供应商都能留下。资本结构和利用率会决定谁穿越周期。

### 2. 有分发、有模型、有企业入口的全栈平台

全栈平台的优势在于同时控制几件事：

- 模型
- 云
- 企业账号和采购路径
- 办公 / 搜索 / 开发 / CRM 等默认工作面
- 数据与权限边界

这类公司包括 `Microsoft`、`Google`、`Amazon`、`Meta`、`Salesforce` 等大平台，以及被它们深度绑定的前沿模型公司。

它们不一定每条产品线都赢，但它们更容易把 AI 能力内置到现有分发面里，把外部 startup 的功能变成平台能力。

### 3. 真正能降低推理成本和提升可靠性的 infra

推理需求越大，企业越会关心：

- token 成本
- 延迟
- 峰值稳定性
- routing
- GPU utilization
- quantization
- batching
- fallback
- on-prem / edge inference

所以 inference optimization、model gateway、routing、serving、cost control 会留下。区别在于，薄的 API reseller 会死，能真实降低成本和稳定性的 infra 会留。

### 4. Eval、observability、debugging 和安全治理

AI 系统越多，失败就越多。失败形式也更难 debug：

- 模型错了
- 上下文错了
- 检索错了
- 工具错了
- memory 污染
- 权限错配
- prompt injection
- 成本失控

因此 eval、trajectory tracing、failure replay、audit log、security、policy enforcement、PII / secret protection 会成为 AI 系统里的 CI/CD 和安全层。

这类层会留下，因为模型越强、agent 越能行动，治理需求越大。

### 5. Context / memory / data governance

长期看，AI 不只是“问答”，而是持续调用上下文、组织知识、记忆状态、处理冲突和过期信息。

这层不会被模型完全吞掉，因为它涉及：

- 什么该记
- 什么不该记
- 什么过期
- 谁能看
- 什么能写回
- 出错后如何追溯
- 用户如何信任系统

模型可以参与判断，但最终的状态、权限、审计和治理需要系统承载。

### 6. Agent runtime / sandbox / workflow harness

如果 AI 要从聊天走向行动，就一定需要 runtime。

能留下的不是“会调用工具”的 demo，而是能处理真实任务的 execution layer：

- browser / terminal / filesystem sandbox
- network policy
- credentials boundary
- approval flow
- long-running jobs
- rollback
- state persistence
- replay
- human handoff

这也是本库反复说的 `Harness` 机会：模型公司做 general intelligence，创业公司更现实的位置是把模型变成某个组织和流程里可用、可控、可验收的系统。

### 7. 已经证明 ROI 的工作流应用

应用层不会整体死亡，但会高度分化。

更可能留下来的应用满足至少一个条件：

- 嵌入高频工作流
- 有清楚 ROI
- 能接入真实系统
- 有行业数据和合规门槛
- 能把结果交付闭环，而不是只生成建议

当前本库材料里最明确的例子是 coding：它已经成为生成式 AI 第一个真正成立的 killer use case。其他更可能留下来的 vertical 包括医疗、法律、金融、会计、政府、科学研发等高价值工作流。

### 8. 有默认工作面的个人和企业 AI 助手

个人 AI 助手不会因为泡沫破裂消失，但会向默认入口集中。

能留下来的不是“又一个聊天页”，而是进入用户真实事件流和工作面的产品：

- 邮件
- 日历
- 文件
- 浏览器
- IDE
- 企业知识库
- CRM / ERP
- 通讯工具

如果一个助手能持续理解 context、主动 resurfacing、管理权限和记忆，它更像个人或企业工作面的智能层。否则只是一个可替换聊天入口。

## 七、按 2000 年互联网泡沫类比的一张表

| 2000 年互联网泡沫 | 当前 AI 泡沫中的对应物 | 可能结局 |
|---|---|---|
| Pets.com / Webvan 这类“方向对但单位经济错”的公司 | 高获客、高推理成本、低留存或高人工交付成本的 AI app / AI service | 需求可能留下，公司估值重定价 |
| 二线门户和内容站 | 没有默认入口、没有工作流控制点的通用 AI app | 被默认入口和平台压缩 |

## 八、一个更实用的判断公式

判断一家 AI 公司会不会穿越泡沫，可以先问八个问题：

1. 它的钱来自客户预算，还是主要来自融资预期？
2. 它是否控制真实资源：算力、数据、权限、状态、分发、workflow、专业验收？
3. 它是否会随着模型变强而更有价值，而不是被模型或平台吃掉？
4. 它是否嵌入真实工作流，还是停留在 demo / chat / novelty？
5. 它是否能降低成本、提升可靠性、减少风险、完成写回，还是只提升“看起来聪明”？
6. 它是否有可验证的 ROI 和验收标准？
7. 它是否在哑铃结构的两端：顶级判断密度、专业服务产品化，或极致自动化低成本？
8. 它是否有默认入口或独特分发，能持续获得用户上下文？
9. 它的交付毛利是否真的像软件，还是依赖大量人类专家和定制服务？
10. 它是否有治理结构：权限、审批、审计、回滚、human handoff？

如果大多数答案是否定，它更像泡沫里的公司。

如果大多数答案是肯定，它更可能是泡沫破裂后留下来的层。

## 九、最短答案

修正后，会死的不只是老式 wrapper，而是：

- 复杂 agent 但没有可靠性、权限、验收和回滚的公司
- 看起来像软件、实际像重服务交付，且毛利无法改善的 AI service 公司
- 只能生成 demo，无法进入 production workflow 的 app generation 平台
- ROI 真实但不可规模化复制的 vertical AI 公司
- 只能回答问题、不能完成业务动作和系统写回的 customer support agent
- 没有分发、工作面、社区或身份心智的 consumer AI app
- 高杠杆、无利用率优势的算力 / 推理公司
- 没有技术、成本、生态、区域合规、垂直场景或分发优势的模型公司

会留下来的，大多是：

- 默认工作面：IDE、repo、browser、office、enterprise search、legal / clinical / support workspace
- 可治理执行环境：sandbox、权限、审批、回滚、日志、eval、human handoff
- 专业服务产品化层：法律、医疗、金融、会计、客服、销售等高价值 workflow
- 模型和推理基础设施：成本、延迟、routing、eval、observability、security
- 有真实分发和用户心智的 consumer / prosumer AI 产品
- 少数强模型、开源生态、区域合规模型和被平台深度绑定的模型能力

最重要的结论是：

> **AI 泡沫破裂后，留下来的不是“AI 公司”这个标签，也不只是“不是 wrapper”。留下来的是能把模型能力变成真实世界里可分发、可治理、可验收、可规模化交付、且毛利结构说得通的工作面和服务系统。**
