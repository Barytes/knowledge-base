## 产品内容
第一版形态是 AI 情报看板：抓 GitHub Trending、Product Hunt、Hacker News、Hugging Face、投资事件、社交平台舆情等公开信号，用新增 star、momentum、项目分类、趋势图、雷达图和项目列表，让用户看到最近 AI 行业什么在变热、什么在回落、哪些项目值得继续观察。

它的目标用户初步是 AI 投资人、研究员、创业者、高管，后来也扩展到自媒体创作者。核心不是“给更多信息”，而是把信息整理成用户看得懂、能判断、能行动的结构。比如财经、科技、金融、自媒体赛道里，用户不是缺信息，而是看不懂、辨不清、选不出。

更长期的想法是把看板变成 context 入口。用户看到趋势后，可以继续追问，上传简历、目标、会议记录、项目背景。系统不只是说“AI Agent 很热”，而是结合这个人的能力、目标和当前任务，判断哪些机会和他有关。这样看板就从行业雷达，变成个人化情报和决策辅助入口。

## **深哥的理解**

从上午讨论看，深哥更关注“原型能不能跑出来、能不能把市场信号处理成可见判断”。他展示的微型原型已经把 GitHub Trending 的 AI 热点做成雷达图、折线图和项目列表。这里的关键不是爬虫，而是“处理和呈现”：用户真正的问题是看不动、看不完、看完也不知道怎么判断。

深哥一贯的底层理解可以概括成“滤波器”：AI 不应该把信息越堆越多，而是过滤掉过于简单或过于复杂的内容，只留下用户需要踮脚够一够就能理解的东西。所以这个看板对他来说，本质上是在减少认知摩擦，而不是做一个更花哨的信息流。

### 核心洞察
1. Belief-anchored sensing: 有自己的 belief，然后用世界的信息去校准它，以及用校准过的belief修正过去对信息的理解
2. Temporal reasoning: 理解信息在时间链条中的演变
3. Reality-model reconstruction：穿透信息重建真实世界模型
4. Judgment externalization: 人对信息的判断是隐性的、混合的、不稳定的。当用户对某个信息产生直觉反应时，系统帮助他沿着这个反应继续调查真实世界，直到这个直觉变得更清楚、更有证据，或者被证伪。

### 突围方向
可以把这六点定义成“个人手搓看板很难长期做好的产品能力”。

**1. 高质量信号源**
不是“RSS 越多越好”，而是持续筛选出对判断有预测价值的来源。

高质量信号源要满足几个条件：

- 早：比大众媒体、newsletter 更早出现
- 准：不是标题党，后续经常被验证
- 近：离原始事实更近，比如官方 changelog、GitHub repo、招聘、用户讨论、论文、产品发布页
- 稀缺：普通人不容易稳定看到
- 可追溯：能回到原文、时间、作者、上下文
- 对当前问题相关：不是泛泛“AI 很火”，而是和某个判断问题有关

例子：
- OpenAI / Anthropic / Google / Meta 官方 blog、docs、release notes
- GitHub 新 repo、stars 增长、issue 讨论、commit 活跃度
- Product Hunt / Hacker News / Reddit / Discord / Superlinear 个人项目
- 论文、benchmark、Hugging Face model / dataset / Spaces
- 公司招聘、融资、定价页变化、用户抱怨
- 投资人、founder、工程师的一手观察

核心不是“收集源”，而是知道哪些源在什么问题上可信。

**2. 判断 Schema**

判断 schema 是把一条信息放进决策框架里的结构，不是让 AI 随口总结。

一条信号进来后，不只是写：

> 某公司发布了一个 memory agent。

而是结构化成：

- 关联问题：这是否影响我们对 agent memory 产品机会的判断？
- 当前 thesis：memory 会被大厂平台层吸收，独立 app 风险高
- 信号类型：大厂产品更新 / 开源项目 / 用户需求 / 融资 / 负面反馈
- 判断关系：支持 / 反驳 / 弱相关 / 待观察
- 影响强度：高 / 中 / 低
- 信心变化：从 60% 到 70%，或不变
- 证据：原始链接、摘录、时间
- 反证：有没有相反信号
- 下一步：继续观察 / 做小实验 / 暂时判死 / 访谈用户

对 AI builder 来说，还可以加几项：

- 是否有真实痛点
- 是否只是 wrapper / slop
- 是否有非 prompt 资产
- 是否能 dogfood
- 是否容易被用户自己手搓
- 是否容易被大厂吞掉
- 是否和我们的能力栈匹配

这才叫“判断 schema”。

**3. 复盘机制**

复盘机制是回答：

> 我们之前为什么这么判断？后来事实证明怎样？

很多资讯产品只管今天推送什么，不管上周的判断是否错了。复盘机制要保存判断历史。

每条重要判断都应该能回看：

- 当时的 thesis 是什么
- 当时依据哪些信号
- 当时忽略了哪些反证
- 当时信心是多少
- 后续出现了什么验证 / 证伪信号
- 判断是否需要更新
- 哪些来源当时误导了我们
- 哪些弱信号后来证明很重要

输出可以是：

- 每周：哪些判断发生变化
- 每月：哪些判断被验证 / 证伪
- 每季度：我们在哪些方向上系统性误判

这会把看板从“资讯流”变成“判断力训练系统”。

**4. 来源可靠性**

来源可靠性不是看一个源“有名没名”，而是看它在特定问题上的历史表现。

可以记录：

- 这个来源是否经常早于主流发现信号
- 它的消息后来是否被验证
- 它偏技术、投资、营销、社区，还是媒体叙事
- 它容易高估还是低估某类趋势
- 它提供的是一手事实，还是二手解读
- 它在哪些领域可靠，在哪些领域噪声大

比如：

- 官方 blog 准，但通常偏自我叙事
- Hacker News 早，但有工程师偏见
- Product Hunt 能看产品热度，但容易被 launch 机制污染
- 投资人文章有框架，但可能服务于持仓和叙事
- GitHub repo 活跃度是行为信号，但不等于商业需求

产品价值在于长期积累“这个源在什么判断上可信”。

**5. 异常簇发现**

异常簇不是一个热点新闻，而是多个弱信号在不同地方同时指向同一件事。

单条信号可能只是噪声。异常簇是：

- Superlinear 有人做 AI Bubble Radar
- GitHub 有人做 trend-monitor
- Product Hunt 出现类似产品
- Hacker News 开始讨论同一个痛点
- 大公司 release note 也开始补这个能力
- 用户在社群里反复抱怨同一种信息过载

这些放在一起，说明“个人/小团队行业情报”可能不是孤立需求，而是在多个场景自然冒出来。

异常簇的关键是：

- 跨来源重复
- 主题相似，但表达不同
- 时间上接近
- 尚未被主流命名为成熟趋势
- 能挑战已有判断

它要发现的不是“什么最火”，而是“什么正在从噪声变成趋势”。

**6. 多人共享判断状态**

多人共享判断状态不是多人共享一个 dashboard，也不是评论区。

它是让一组人围绕同一组问题维护共同的判断版本。

包括：

- 当前正在判断的问题
- 每个问题下的 thesis
- 支持证据
- 反证
- 争议点
- 谁添加了什么信号
- 谁改变了什么判断
- 当前信心是多少
- 下一步行动是什么
- 历史版本如何变化

它应该允许分歧存在。

比如深哥觉得某方向值得看，你觉得它像 slop。系统不应该把分歧压成一个 AI 总结，而应该保存：

- 深哥的判断依据
- 你的反对理由
- 后续要观察的验证信号
- 到哪个时间点复盘

这就从“个人情报流”变成了“小团队判断协作系统”。

最关键的区别是：

普通看板共享的是信息。  
判断工作台共享的是“我们现在如何理解这件事，以及为什么”。

### 趋势研究有什么用呢？
我是 curiosity-driven，靠内心的好奇、违和感、兴趣和联想来决定研究什么。我需要的是深入理解一个东西，穿透表面信息，看到背后的真实世界。我的行动起点是“我想搞明白这个”。
趋势研究是 opportunity-driven。它的起点不是“我想理解这个”，而是“外部世界这么大，我应该把注意力分配到哪里”。它不先追求理解，而是先做筛选。
其实deep down我不理解为什么趋势研究能产生洞察。
