# 仓库地图输出模板

当 `repo-map-ingest` 创建或更新维护过的 repo note 时，使用这个结构。

## 摘要

- 仓库在做什么
- 当前研究的主题是什么
- 这版地图能支撑到什么置信度

## 仓库目的

- 来自 README 或文档的显式定位
- 从代码与 repo contract 里观察到的实际定位

## 架构地图

- 主要目录或子系统
- 在有必要时补上执行流
- 标出 agent 控制层或评估层在哪里

## 机制清单

对每个机制，至少记录：

- 它控制什么
- 它在补偿哪种失败模式
- 证据位于哪里
- 它引入了什么代价

## 证据锚点

- repo URL
- branch、tag、commit 或观察日期
- 值得回查的具体文件
- 若可得，关键 PR、issue、ADR 或 release

## 开放问题

- 仍需更深文件阅读才能回答的缺口
- README 与实现可能分歧的地方

## 相关页面

- 相关的 `wiki/knowledge/` 主题页
- 相关的 `wiki/bridges/` 页面
